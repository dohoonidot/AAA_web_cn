# AAA 어드민 포트/네트워크 이슈 정리

## 1. 문제 상황

집에서 `npm run dev`로 로컬 서버를 띄운 뒤 어드민 웹에 접속하면, **모든 DB 조회 API에서 ETIMEDOUT 에러**가 발생함.

```
Error: connect ETIMEDOUT 211.43.205.49:5432
```

- 회사(사내망)에서는 정상 동작
- 집에서는 DB 연결 타임아웃

---

## 2. 서버 구성

| 서버 | IP | 도메인 | 역할 | 포트 |
|------|-----|--------|------|------|
| **49번 서버** | `211.43.205.49` | `ai2great.com` | PostgreSQL DB + AAA 웹 + 선물 API | 5432, 443/8060, 9999 |
| **어드민 웹 서버** | `210.107.96.193` | (없음) | AAA 어드민 Node 앱 | 9999 |

- 어드민 앱은 **193 서버**에서 돌아가면서, DB와 외부 API는 전부 **49번 서버(ai2great.com)**를 바라보는 구조
- `.env`의 `PGHOST=211.43.205.49` → 193 서버의 Node가 49번 서버 DB에 **원격 접속**
- `.env`의 `UPSTREAM_HOST=ai2great.com` → 로그인/휴가 API도 49번 서버로 프록시

---

## 3. 원인

### 집에서 로컬(localhost:3000)로 띄울 때

- Node가 **내 PC**에서 돌아감
- DB 조회: 내 PC → `211.43.205.49:5432` → **회사 방화벽이 차단** → ETIMEDOUT
- 외부 프록시 API: 내 PC → `ai2great.com:8060` → 인터넷에 열려 있어서 **정상 동작**

### 서버(210.107.96.193:9999)에 접속할 때

- 사내망에서는 정상 동작
- 집에서 `http://210.107.96.193:9999` 접속 → **193 서버의 9999 포트가 외부에서 막혀 있음**

---

## 4. 로컬 포트가 3000인 이유

- `nodemon.json`에서 `"PORT": "3000"` 을 환경변수로 주입
- `server.js`의 `const PORT = process.env.PORT || 9999`에 의해 개발 시 3000, 서버 운영 시 9999 사용
- 의도된 설정 (개발/운영 포트 분리)

| 실행 방법 | 포트 결정 | 결과 |
|-----------|-----------|------|
| `npm run dev` (로컬 개발) | `nodemon.json` → `PORT=3000` | **3000** |
| `npm start` (서버 운영) | `.env` → `PORT=9999` | **9999** |

---

## 5. 프로젝트 구조

### Express 하나가 전부 처리하는 구조

```
AAA_admin/
├── client/    ← 프론트엔드 (HTML, CSS, JS) - 정적 파일
├── server/    ← 백엔드 (Express)
│   ├── server.js      ← 메인 서버 (정적 파일 서빙 + API + 프록시)
│   ├── config/db.js   ← PostgreSQL 연결
│   ├── routes/        ← API 라우트
│   ├── controllers/   ← 컨트롤러
│   ├── models/        ← DB 쿼리 (model.js)
│   └── middleware/    ← 인증 미들웨어
├── .env               ← DB, 포트 설정
└── nodemon.json       ← 개발 환경 (PORT=3000)
```

- nginx 설정은 이 프로젝트 안에 **없음** (49번 서버에서 별도 관리)

### API 두 종류

#### 1) DB 직접 조회 API (내가 만든 것)

| 경로 | 설명 |
|------|------|
| `/api/dashboard/*` | 대시보드 통계 (총 메시지, 접속자, 카테고리별 질문, 연령별 사용량) |
| `/api/main/*` | CSR, 미사용자, 앱 버전, 개인정보 동의, 생일자, 추석선물 |
| `/api/users/*` | 사용자 목록/조회 |
| `/api/conversations/*` | 대화 내역 |
| `/api/gifts/*` | 선물 (일부 DB + 일부 프록시) |
| `/api/admin/deleteUser` | 사용자 삭제 |
| `/api/getUpdatePrivacyCount` | 개인정보 동의 수 업데이트 |

→ `server/models/*.model.js`에서 `db.query(SQL)`로 PostgreSQL(49번 서버) 직접 조회

#### 2) 외부 서버 프록시 API (ai2great.com:8060으로 전달)

| 경로 | 설명 |
|------|------|
| `/admin/login` | 로그인 |
| `/admin/leave/*` | 휴가 관련 (신청, 승인, 관리) |
| `/admin/updateUser` | 사용자 수정 |
| `/admin/createUser` | 사용자 생성 |

→ `https.request()`로 ai2great.com:8060에 그대로 전달

## 6. AAA 웹 vs AAA 어드민 비교

| 구분 | 서버 | 접속 주소 | 실제 포트 | 집에서 접속 |
|------|------|-----------|-----------|------------|
| AAA 웹 | 49번 (211.43.205.49) | `https://ai2great.com/chat` | 443 (HTTPS 기본) | **가능** |
| AAA 어드민 | 193 (210.107.96.193) | `http://210.107.96.193:9999` | 9999 | **불가** |

- AAA 웹은 443(HTTPS 기본 포트)으로 서비스 → 방화벽에서 이미 열려 있음
- AAA 어드민은 9999로 서비스 → 방화벽에서 막혀 있음

---

## 7. 내 코드에서 할 것

**없음.** 코드는 이미 전부 준비된 상태:

- `0.0.0.0:9999` 리스닝 → 완료
- DB 조회 API → 193 서버에서 49번 서버 DB로 접속 (서버 간 통신) → 정상
- 외부 프록시 API → ai2great.com:8060 호출 → 정상
- 프론트 서빙 → Express가 처리
- 프론트 API 호출 → 상대 경로(`/api/...`) 사용 → 도메인/포트 무관

---

## 8. 해결 방법

### 방법 1: 9999 포트 직접 개방 (간단)

서버/보안 담당자에게 요청:

> **"어드민 서버(210.107.96.193) TCP 9999 포트 외부 개방 요청"**

→ 방화벽만 풀리면 `http://210.107.96.193:9999`로 집에서 접속 가능
→ 로그인, DB 조회, 휴가 관리 등 **전부 정상 동작**

### 방법 2: nginx 리버스 프록시 (보안적으로 더 나음)

서버/인프라 담당자에게 요청:

> **"nginx에서 `https://도메인/admin` → `http://210.107.96.193:9999` 프록시 설정 추가 요청"**

→ 9999를 직접 노출하지 않고 443(HTTPS)을 통해 접속
→ nginx 설정은 서버에서 별도 관리 (내 코드에 없음)

---

## 9. 요약

- **에러 원인**: 집에서 로컬로 띄우면 내 PC → 49번 서버 DB(5432) 연결이 방화벽에 막힘
- **서버에 올린 어드민 접속 불가 원인**: 193 서버의 9999 포트가 외부에서 방화벽에 막힘
- **내 코드 수정**: 불필요 (이미 전부 준비됨)
- **해결**: 서버/보안 담당자에게 **210.107.96.193:9999 포트 개방** 또는 **nginx 프록시 설정** 요청
- **방화벽만 풀리면 만사 OK**
