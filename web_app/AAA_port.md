# 🚨 내부망 접속 오류 트러블슈팅: 회사에선 되는 기능이 집에선 안 되는 진짜 이유

## 📍 1. 현상 파악 (문제의 시작)
- **상황:** 집에서 개발 중, 프론트엔드 코드(`AAA 어드민` - `localhost:3000`)를 띄우자 **일부 데이터는 정상적으로 조회되는데 일부 데이터는 조회가 전혀 안 됨**.
- **정상 작동 환경:** 회사 내부망(사내 네트워크)에서 접속할 때는 전부 정상 조회됨.
- **오류 확인 (에러 로그):** 브라우저 개발자 도구의 Network(네트워크) 탭을 확인해보니 아래와 같은 에러 발견.
  ```json
  Request URL: http://localhost:3000/api/main/dashboard
  Status Code: 500 Internal Server Error
  ```

---

## 🧐 2. 문제 원인 분석 (왜 집에서는 안 될까?)

### 🗃️ 배경 설명: 식당과 재료 창고 구조
- **식당 (프론트엔드 화면):** 내가 집 컴퓨터에 띄운 `localhost:3000`
- **재료 창고 (백엔드 서버 / API / DB):** 데이터를 내어주는 실제 회사 서버 (IP: `210.107.96.193:9999`)

### ⛔ 원인: 사내 방화벽 (경비 아저씨)의 외부 접속 차단
- 회사 서버(210.107.96.193) 자체는 살아있지만, **데이터를 내어주는 "9999번 포트"는 사내망(회사 IP)에서만 접근을 허락하도록 방화벽이 막혀 있음**.
- 따라서, 식당(집)에서 데이터를 달라고 회사 창고로 전화를 걸면 **방화벽이 외부(집 IP)라는 이유로 통신을 콱 끊어버림**.
- 연결이 끊기니 내부 심부름꾼(서버 라우터)이 *"DB랑 연결이 안 돼서 나 터졌어!"* 라고 소리치는 것이 바로 **500 Internal Server Error**의 정체.

> **💡 핵심 요약:**
> 화면(프론트 코드)을 집에서 띄운 것일 뿐, 그 코드가 **사내망 전용 DB 포트나 서버 시스템에 접속(Connection)하려다가 실패했기 때문에 발생하는 에러**. 프론트엔드 코드 오류가 절대 아님.

---

## 🛠️ 3. 해결 방안 (어떻게 해야 집에서도 다 보일까?)

현재 AAA 어드민 웹 구조는 **단일 Node.js 앱(`server.js`)이 프론트 서빙 + 직접 DB 쿼리 + 외부 서버 프록시 모두를 처리하는 모놀리식(Monolithic) 형태**이며, 9999번 포트로 떠 있음.

### ❓ 잠깐! 외부 IP(211.43.205.49)와 내부 IP(210.107.96.193)는 무슨 관계일까?
이 두 IP의 관계는 보통 회사 서버실에서 나타나는 **보안/방화벽 IP 분리 구조**입니다.

1. **`211.43.205.49` (외부 공인 IP / 방화벽 앞단)**
   - 외부에서 `ai2great.com`을 쳤을 때 가장 먼저 도달하는 경비실 입구 IP.
   - 80(HTTP), 443(HTTPS) 포트만 열려 있으며 누구나 `ai2great.com`에 접근 가능하게 해줍니다.

2. **`210.107.96.193` (내부 사설/보안망 IP)**
   - 인터넷과 직접 닿아있지 않고 회사 보안망 쪽에 안전하게 숨겨져 있는 **실제 서버의 주소**.
   - 현재 프론트엔드가 접속을 시도하다 실패한 어드민 DB(9999 포트)가 위치한 곳.

**➡️ 결론:** 경비실(211.43.205.49)에 "ai2great.com/admin-api 로 요청이 오면 그걸 저 안쪽 서버(210.107.96.193)의 9999로 던져줘!" 하는 룰 하나만 추가하는 것이 가장 완벽한 해결책입니다.

---

가장 현실적이고 완벽한 3가지 해결책:

### 💡 1순위 추천 (정석 실무 방식): Nginx 리버스 프록시 연동
- 본인이 아니라 **서버/인프라 담당자에게 Nginx 설정 수정을 요청**하는 방식.
- **원리:** 외부에서 누구나 접근 가능한 정문(`https://ai2great.com`) 바로 뒤에서, 9999번 포트 서버로 몰래 연결하는 방법.
- **장점:** 
  - 해커가 9999번 포트를 볼 수 없어서 완벽한 보안 유지.
  - 별도로 통신망에 SSL/HTTPS 인증서를 추가 발급/관리할 필요 없음.
  - 300명 이상이 동시 접속해도 백엔드가 안정적으로 요청을 분산 처리.
  - **요청예시:** _"ai2great.com/admin-api 로 들어오는 외부 요청을 내부 서버 localhost:9999 로 Proxy Pass (리버스 프록시) 시켜주세요!"_

### ▶️ 2순위: 사내망 VPN 연결 (가장 빠른 즉시 해결)
- 집 컴퓨터에 회사망으로 접속하는 SSL VPN 도구를 켜면, 내 컴퓨터가 잠시 "회사 내부에 있는 컴퓨터"로 위장됨.
- 방화벽이나 소스 코드 수정 없이 그 즉시 500 에러가 사라지고 모든 데이터가 정상 조회됨.

### ▶️ 3순위: 9999번 포트 강제 외부 개방
- 회사 인프라 담당자에게 `210.107.96.193` 서버의 **9999번 포트에 대한 인바운드 방화벽(포트 포워딩)** 자체를 통째로 개방해달라고 요청.
- 하지만 보안상 큰 리스크가 있고 HTTPS 설정이 번거로워 1순위인 역방향 프록시(Reverse Proxy) 방식에 밀림.

---

## 👨‍💻 4. Nginx 프록시 적용 후, 내가(개발자) 수정해야 할 코드

인프라 담당자가 Nginx에서 프록시 길을 뚫어 줬다면, **본인(AAA 어드민) 코드는 아주 약간만 수정하거나 아예 안 고쳐도 됨**.

1. **프론트엔드 API 호출 주소(Base URL) 변경** 
   - `fetch('http://210.107.96.193:9999/api/...')` 처럼 IP와 포트가 하드코딩 되어있다면 ➡️ `fetch('https://ai2great.com/admin-api/...')` 처럼 약속된 도메인 경로로 수정. 
   - (만약 도메인 없이 `/api/...` 같은 상대 경로로만 적어두었다면 Nginx가 알아서 매핑하므로 프론트는 고칠 게 없음!)
   
2. **백엔드(`server.js`)의 `CORS` (접근 허용 도메인) 설정 수정**
   ```javascript
   // 이제 집 localhost 띄운 화면도, 실제 도메인 요청도 모두 통과하도록 허락해야 함
   const corsOptions = {
     origin: ['http://localhost:3000', 'https://ai2great.com'], 
     credentials: true,
   };
   app.use(cors(corsOptions));
   ```
   이 설정만 열어두면 브라우저 CORS 보안 에러(빨간 글씨 에러창) 없이 예쁘게 데이터를 받아올 수 있음.

---
**최종 요약 노트:**
- 집에서 500 에러가 나는 건 프론트 코드 문제가 아니라 내부 DB 접속용 서버 방화벽에 막힌 것!
- 이 구조에서 진정한 해결책은 인프라 담당자에게 Nginx 프록시 패스를 뚫어 달라고 요청(가장 추천)하거나, 본인이 집에서 VPN을 켜는 것이다.
- 통로가 열리면 프론트 단의 하드코딩된 API 주소와 `server.js`의 `cors` 설정만 간단히 확인하면 개발이 끝난다.
