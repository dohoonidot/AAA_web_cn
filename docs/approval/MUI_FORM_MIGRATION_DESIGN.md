# MUI 전자결재 양식 전환 설계 (파일럿: 구매신청서)

## 목표
- `approvalTemplates.ts`의 HTML 렌더 의존 제거
- `휴가 부여 상신`은 변경하지 않고, 상단 공통필수영역 UX를 기준으로 유지
- 결재상세영역은 MUI 동적 폼으로 구성
- 파일럿(`구매신청서`)에서 다음을 필수 지원
  - 반복 테이블의 행/열 추가 및 삭제
  - 사용자 정의 일반 항목(라벨/값) 추가 및 삭제

## 구현 원칙
- 상단 공통필수영역(기안부서/기안자/기안일/제목/결재종류/승인자/참조자)은 기존 흐름 유지
- 하단 결재상세영역은 스키마 기반 렌더
- `approvalTemplates.ts`는 레거시 구조 참고 자료로만 사용
- 런타임 편집 결과는 구조화 데이터(JSON)로 관리

## 데이터 모델
- `ApprovalFormData`
  - `fields`: 일반 필드 키/값
  - `fixedTables`: 고정 테이블 섹션별 키/값
  - `repeatableSections`: 반복 테이블 섹션별 데이터
    - `columns`: 현재 컬럼 정의(사용자 추가 컬럼 포함)
    - `rows`: 행 데이터
    - `customItems`: 사용자 추가 일반 항목(라벨/값)

## 파일럿 적용 범위
- 구매신청서의 `items` 반복 섹션
  - 사용자 컬럼 추가(텍스트/숫자/금액/메모)
  - 사용자 컬럼 삭제
  - 행 추가/삭제
  - 추가 입력 항목(라벨/값) 리스트 편집
- 결재상세 전체 데이터는 `content` 상태에 JSON 문자열로 동기화

## 확장 전략
- 동일 패턴으로 다른 결재종류 섹션에 확장
- 향후 서버 제출 스펙 확정 시 `content` JSON을 기준으로 매핑 구현
